# Content Block Testing — Real Editor Approach

Standing instructions Krishna shared for **every** theme / template upgrade. Test all available Content Blocks as a **real TYPO3 content editor**.

Goal: expected fields exist, each field works with valid and invalid input, values persist, and FE renders correctly.

## 1. Dedicated test page

- Create **one** Content Block testing page in BE.
- Keep it **hidden** (`nav_hide` / disabled) so it is not public.
- Parent must be the **site root** or a folder under it (e.g. Home → `misc`). **Never create QA pages on pid 0 / outside the site root** (causes `/autogenerated-*` and “No site configuration”).
- Test **one Content Block at a time**.
- Do **not** wait until all CEs are done before filing majors.

## 2. Identify expected fields

Before each CE, list FormEngine-visible fields and their type: text, RTE, number, select, checkbox, link, image/media, file, date, required/optional, repeatable/IRRE, conditional.

Check label, type, default, required, placeholder/help, options, validation, conditional behavior.

**IRRE:** use the element’s **Create new** (exact), not Image **Create new relation**.

## 3. Field cases (happy + negative)

For each field type: valid value, empty, spaces-only, special/HTML chars, long text, invalid type, min/max. RTE: headings, lists, links, paste. Select: every option, defaults, missing/wrong labels. Image: upload FAL **before** filing “missing on FE”; replace/remove; alt. Required: empty save must validate; other fields must not be lost. Optional: empty must save without FE/layout break. Repeatable: add / edit / reorder / delete / empty collection.

## 4. CE-level

Create → fill realistic content → save → reload BE → edit → save → FE. Duplicate/move/delete when in scope. Invalid data must not Whoops the BE or FE.

## 5. Frontend + responsive

Verify text, formatting, images, links, spacing, layout, optional/empty, no broken HTML/assets. Desktop + tablet + mobile. Prefer **element-only** evidence (`fe-el-*.png`) with red highlight.

## 6. Immediate issue reporting

**Find → Add ClickUp issue → resume.** Critical/Major: record immediately (CE name, field, steps, actual, expected, severity, screenshot/URL). Continue other CEs. Do not stockpile majors until the full list is done.

## 7. After all CEs

Multiple instances, mixed CEs, reorder, multilingual if present, then **retest issues assigned to the QA owner** (`testing` / resolved), then **delete QA pages**, then parent “testing complete / ready for client update”.
